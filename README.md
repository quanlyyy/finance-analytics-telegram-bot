# Expense Analytics

## Поддержка автора

Кнопка «Поддержать автора» и команда `/donate` открывают DonatePay (`https://donatepay.ru/don/1537607`) и выбор суммы 25, 50, 100, 250 или 500 Telegram Stars. Своя сумма: `/donate 150` (целое число от 1 до 10000). Оплата добровольная и не открывает дополнительные функции.

Счета выставляются в `XTR`, владелец и сумма проверяются перед оплатой. Подтверждённые платежи и идентификаторы Telegram сохраняются отдельно от финансовых операций в таблице `donations`. Команда `/donations` и кнопка «История донатов» показывают собственные платежи пользователя с перелистыванием по 10 записей. Контактов и обращений в поддержку в этом разделе нет. Возврат через бота отключён; старые кнопки и `/paysupport` открывают только историю. Платежи DonatePay просматриваются на стороне DonatePay. Для webhook обязательно получать `pre_checkout_query`; скрипт `scripts.configure_bot` настраивает это и команды меню. Новая таблица создаётся при запуске, существующие данные не изменяются.

Скриптов инициирования возврата в проекте нет. Уведомления о возвратах, выполненных самой платформой, учитываются через `refunded_payment`, чтобы история платежей сохраняла корректный статус.

Telegram-бот и мини-приложение для личных финансов. React + TypeScript, FastAPI, aiogram, SQLAlchemy. Красно-чёрный адаптивный интерфейс.

## Текущий этап

Работают операции в рублях, редактирование и удаление, месячная аналитика и категории, общий месячный лимит, объяснения по правилам, экспорт JSON и удаление данных. Бот принимает сообщения «кофе 250», «зарплата 80000», поддерживает отмену и `/report`. Данные бота и приложения общие. Авторизация приложения проверяет подпись и срок Telegram initData на сервере.

Добавлены цели с ручным учётом накоплений, план регулярных платежей с подтверждением оплаты и переносом даты на месяц, CSV-импорт по общему шаблону с предварительным просмотром и пропуском точных дубликатов, сравнение месяцев и оценка покупки по месячному лимиту. Полный экспорт включает цели, платежи и бюджет. Голос, OCR и ИИ имеют отключённую границу провайдера; платные вызовы отсутствуют. Ещё не реализованы: несколько счетов и переводы, автоматические уведомления, банковские PDF/XLSX, прогноз к дате дохода и английская локализация. Расширенная версия пока не завершена. История в интерфейсе ограничена последними 1000 операциями; аналитика и экспорт учитывают все записи.

## Структура

- `backend/` — API, бот, авторизация, модели, расчёты.
- `frontend/src/` — интерфейс React и стили.
- `tests/` — проверки финансовых расчётов, авторизации и разделения пользователей.
- `deploy/` — HTTPS reverse proxy для сервера.
- `data/` — локальная база, исключена из Git.

## Локальный запуск

Требуются Python 3.12+, Node.js 22+ и pnpm 11.25.0.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env # только если .env ещё не создан
cd frontend
pnpm install
pnpm build
cd ..
.\.venv\Scripts\python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Существующий `.env` не перезаписывать. Для локальной проверки включить `DEV_AUTH=true` в `.env`, перезапустить API и открыть `http://127.0.0.1:8000/?demo=1`. Это отдельный локальный профиль с ID 1. На публичном сервере DEV_AUTH должен быть false; compose принудительно отключает его. Без demo приложение требует вход из Telegram.

Бот запускается отдельно: `.\.venv\Scripts\python -m backend.bot`. Токен находится только в `.env`. Одновременно запускать только один polling-процесс. Команда запуска бота начнёт отвечать пользователям.

Проверки: `.\.venv\Scripts\python -m pytest -q`, в `frontend` — `pnpm build`. Снимок установленных Python-зависимостей сохранён в `requirements.lock.txt`.

Для уже настроенного Windows-проекта: `./start-preview.ps1` запускает локальный тестовый профиль, `./start-bot.ps1` запускает бота. Production работает на VPS `app.botsapptesses.ru`: мини-приложение обслуживает FastAPI за Caddy, бот получает обновления через polling. Telegram API доступен серверу через прокси, заданный только в `.env`. Docker запускается автоматически. SQLite хранится в постоянном Docker-томе; ежедневные резервные копии находятся в `data/backups` внутри того же тома.

## Хостинг и домен

Выделен сервер 161.104.46.70; публичная A-запись app.botsapptesses.ru проверена. SSH настроен; проверены Ubuntu 24.04, 2 ГБ RAM и диск 25 ГБ. Подготовлена схема одного Linux VPS с SQLite и Docker Compose. PostgreSQL поддерживается через `DATABASE_URL=postgresql+psycopg://...`, но для первого небольшого запуска SQLite проще и дешевле. Для роста нагрузки потребуется PostgreSQL и миграции Alembic.

Адрес приложения — `app.botsapptesses.ru`. DNS указывает на сервер, приложение опубликовано с действующим HTTPS. Бот получает обновления через polling; исходящий запрос к Telegram идёт через HTTP-прокси, адрес и пароль которого хранятся только в `.env` на сервере.

1. Создать VPS с Docker, постоянным диском и публичным IP; направить DNS-запись `app` на адрес сервера и открыть входящие порты 80/443.
2. Скопировать проект и отдельно заполнить `.env`: токен бота, HTTPS-адрес приложения, секрет webhook API, режим polling и HTTP/SOCKS-прокси, если серверу нужен такой маршрут к Telegram.
3. Запустить приложение и бота командой `docker compose --profile polling up -d --build api bot`. Caddy получает TLS-сертификат при корректном DNS.
4. Настроить URL мини-приложения в BotFather. Docker volume сохраняет SQLite при пересоздании контейнеров; не удалять его командой `down -v`.

Перед открытым запуском нужны ограничения частоты запросов, мониторинг, политика обработки данных, миграции БД и проверка на реальном телефоне. Docker-сборка, публикация и проверка HTTPS выполнены. Голос/OCR/ИИ требуют отдельного провайдера и бюджета; ключи для них не добавлены.

## Особенности данных

Все денежные суммы API хранятся целыми копейками. Разница доходов и расходов за месяц не является балансом банковского счёта. Сервер выбирает пользователя из проверенной подписи Telegram, а не из тела запроса. Финансовые сообщения бот принимает только в личном чате. Для старых схем изменения моделей автоматически не мигрируются.

Официальная схема проверки Telegram: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app

## Дополнительные проверки и резервные копии

Согласованная копия SQLite создаётся командой `python -m scripts.backup`; проверяется `PRAGMA integrity_check`. На сервере включён systemd timer `expense-analytics-backup.timer`: ежедневно в 03:15 UTC (06:15 МСК) с задержкой до 5 минут. Копии пока хранятся на том же VPS, внешнее хранилище не настроено.
